# 개인정보·보안

> 건강정보는 민감정보다. 본 문서는 구현 통제이며 출시 전 한국 개인정보·의료·전자상거래 전문가 검토가 필요하다.

## 동의와 권리

가입 필수 동의, 만 14세 이상 확인, 채널별 마케팅 선택 동의를 분리한다. 첫 케이스에서 민감정보 처리와 환자 동의/적법한 보호 권한을 별도로 받는다. 제휴 신청마다 수신자별 제3자 제공 동의를 받는다. 목적·항목·기간·거부권·기능 제한과 문서 버전/원문/채널/시각을 보존한다.

철회는 즉시 새 처리와 공유를 차단한다. 사용자는 열람, 정정, 처리정지, 동의 철회, 내보내기, 공유 회수, 탈퇴·삭제, 마케팅 채널 철회를 할 수 있다. 접수번호, 기한, 담당 이력을 남긴다.

## 권한

OWNER는 삭제·권한, CO_ADMIN은 문서·일정·구성원, CAREGIVER는 기록·업무·비용, VIEWER는 승인 요약만 접근한다. 모든 읽기/쓰기에서 서버와 DB 정책을 검사한다. 관리자 역할은 서버 RBAC와 강한 인증으로 분리한다.

사진 OCR은 브라우저 안에서 수행하고 원본 사진을 서버에 전송하지 않는다. 사용자가 확인한 텍스트만 케이스 권한 경계 안에 저장한다. 제휴 상품은 모든 사용자에게 동일한 비의료 입원 생활용품만 보여주며 질환·문서·기록을 추천에 사용하지 않는다. 페이지 안에 제3자 추적 스크립트를 삽입하지 않고, 사용자가 고지된 제휴 링크를 직접 눌렀을 때만 쿠팡으로 이동한다.

## 위협 모델과 통제

| 위협 | 통제 |
|---|---|
| IDOR/테넌트 혼선 | 모든 질의의 caseId+membership 검사, 음성 권한 테스트 |
| 초대 탈취 | 256-bit 난수, 해시 저장, TTL, 단일 사용, 회수, noindex |
| XSS/CSRF/SQLi | 출력 인코딩, CSP, SameSite/CSRF 검증, ORM 파라미터화 |
| 파일 공격 | 허용목록, 매직바이트, 크기/페이지 제한, 격리, 서명 URL |
| SSRF/AI 인젝션 | 임의 URL 금지, 네트워크 제한, 문서 지시 비신뢰 |
| 계정 공격 | rate limit, 재인증, 세션 회수, 실패 알림, 관리자 MFA |
| 로그/분석 유출 | 허용 속성 목록, 마스킹, 원문 금지, 접근·보존 제한 |
| 결제 위조 | PG 서명, 멱등키, 서버 상태 전이, 금액/상품 재검증 |

전송 TLS, 관리형 저장 암호화, 비밀 저장소, 최소권한, 의존성/취약점 점검을 적용한다. 사고 시 탐지→차단→보존→영향평가→법정 통지 판단→회고 절차를 수행한다. 실제 연락망과 DPO/고충처리 담당은 출시 전 확정한다.
